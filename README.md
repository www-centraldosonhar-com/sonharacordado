# Central do Sonhar

Flask application for volunteer coordination.

## Production stack

- Flask / Python
- Render Free Web Service
- Neon PostgreSQL
- Supabase Storage
- GitHub

## 1. Create the Neon database

Create a Neon project and copy the PostgreSQL connection string.

Use the pooled connection string when available.

Add it locally to `.env`:

```env
DATABASE_URL=postgresql://...
```

The application creates its tables automatically from:

```text
database/schema.sql
```

## 2. Create Supabase Storage

Create a Supabase project.

In Storage, create a bucket named:

```text
central-media
```

Make the bucket **public**, because avatars and event covers are public
assets shown by the website.

Copy these server-side values into `.env`:

```env
SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_SERVICE_ROLE_KEY=...
SUPABASE_BUCKET=central-media
```

Never put the service-role key in HTML, JavaScript, or GitHub.

## 3. Local setup

Create `.env` from `.env.example`.

Install:

```bash
python -m pip install -r requirements.txt
```

Run:

```bash
python app.py
```

## 4. Move existing SQLite data to Neon

Keep your existing `database.db` in the project root temporarily.

With `DATABASE_URL` configured in `.env`, run once:

```bash
python migrate_sqlite_to_neon.py
```

After confirming the data exists in Neon, `database.db` should remain
ignored by Git and can be kept only as a local backup.

## 5. GitHub

Important files to commit:

```text
app.py
requirements.txt
render.yaml
.python-version
.env.example
.gitignore
database/schema.sql
templates/
static/
migrate_sqlite_to_neon.py
```

Do **not** commit:

```text
.env
database.db
```

## 6. Render

Create the service from the GitHub repository or use `render.yaml`.

Build command:

```text
pip install -r requirements.txt
```

Start command:

```text
gunicorn app:app
```

Configure these environment variables in Render:

```text
DATABASE_URL
SEED_ADMIN_PASSWORD
SUPABASE_URL
SUPABASE_SERVICE_ROLE_KEY
SUPABASE_BUCKET
```

`SECRET_KEY` can be generated by Render when using the Blueprint.

## Notes

Render's free web service filesystem is ephemeral, so production media
is uploaded to Supabase instead of relying on local folders.

The app still uses local static folders as a development fallback when
Supabase variables are not configured.
